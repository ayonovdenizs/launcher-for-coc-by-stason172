# Настройка лаунчера: `config.launcher`

Лаунчер ничего не знает о конкретном моде: всё, что видит пользователь —
заголовки, кнопки, арт, цвет, проверяемые файлы, откуда качать обновления —
описывает файл **`config.launcher`** рядом с лаунчером (в корневой папке игры).

Лаунчер без конфига не запускается: при ошибке он показывает путь, строку,
причину и кнопки «Создать пример» / «Открыть файл».

## Быстрый старт для автора мода

1. Положите `Launcher.exe` в корневую папку игры.
2. Создайте заготовку: `Launcher.exe --create-config`
3. Откройте `config.launcher`, поправьте поля под свой мод.
4. Проверьте файл: `Launcher.exe --check-config` — печатает сводку и выходит.

Формат — **JSON с комментариями**: `//`, `/* */` и висячие запятые разрешены,
поэтому прямо в файле можно писать пояснения (а `--check-config` вернёт номер
строки, если что-то сломалось).

## Поля верхнего уровня

| Поле | Тип | По умолчанию | Что делает |
| --- | --- | --- | --- |
| `name` | строка | `"Лаунчер"` | Название в заголовке окна и панели задач |
| `hint` | строка | `"Выберите режим запуска"` | Подсказка внизу до наведения на кнопку |
| `footer` | строка | `"Версия {version}"` | Подпись внизу; `{version}` — версия лаунчера, `{name}` — название |
| `accent` | `#rgb` / `#rrggbb` | `#c9821f` | Акцентный цвет: главная кнопка, подсветки, полоса слева |
| `window` | объект | — | Размеры окна |
| `hero` | объект | — | Тексты шапки |
| `assets` | объект | — | Своя графика |
| `game` | объект | — | Что запускаем и что обязательно |
| `update` | объект | — | Проверка обновлений |
| `options` | список | — (обязательно) | Кнопки меню, порядок = порядок в окне |

Неизвестные поля не ломают лаунчер: о них пишут в `launcher.log` как о
предупреждении — удобно ловить опечатки вроде `"titel"`.

### `window`

| Поле | Тип | По умолчанию | Диапазон |
| --- | --- | --- | --- |
| `width` | целое | `470` | 340…1100 |
| `hero_height` | целое | `150` | 0…420 (0 — шапки нет) |

Высота окна считается по числу кнопок и ограничивается экраном: если кнопок
много, список становится прокручиваемым.

### `hero`

| Поле | Что это |
| --- | --- |
| `kicker` | Мелкая надпись над заголовком (`S.T.A.L.K.E.R.`) |
| `title` | Крупный заголовок; по умолчанию равен `name` |
| `subtitle` | Подпись под заголовком |

Пустая строка — блок просто не показывается.

### `assets`

| Поле | Что это |
| --- | --- |
| `background` | Фон окна: `.jpg`/`.png`. Путь относительно `config.launcher`; `~` и переменные окружения работают |
| `icon` | Иконка окна: `.ico` (лучше) или `.png` |

`null` или отсутствие поля — берётся встроенный арт лаунчера. Фон растягивается
по размеру окна с сохранением пропорций (лишнее обрезается), поверх ложится
затемнение, поэтому светлый арт не мешает читать текст.

### `game`

| Поле | Что это |
| --- | --- |
| `executable` | Файл запуска по умолчанию для кнопок `action: "run"` без своего `target` |
| `required_files` | Список файлов/папок, без которых запуск бессмысленен: лаунчер проверит их перед стартом и покажет, чего не хватает |

Проверяются только файлы, указанные в `required_files` (и в `required_files`
у конкретной кнопки) — ничего лишнего никто не проверяет.

### `update`

| Поле | Тип | По умолчанию | Что это |
| --- | --- | --- | --- |
| `enabled` | bool | `true` | Выключить проверку обновлений совсем |
| `repo` | строка | — | `"владелец/репозиторий"` на GitHub — оттуда берётся последний релиз |
| `timeout` | число | `6.0` | Таймаут запроса в секундах (минимум 1) |

Если есть кнопка с `action: "update"`, поле `repo` обязательно. Лаунчер не
подменяет сам себя: он в фоне спрашивает GitHub, пишет «Доступна версия X» и
открывает страницу релиза. Ошибка сети — не более чем запись в лог.

### `options` — кнопки

| Поле | Тип | По умолчанию | Что это |
| --- | --- | --- | --- |
| `title` | строка | — (обязательно) | Надпись на кнопке |
| `description` | строка | `""` | Подпись под надписью + подсказка в статусной строке |
| `action` | строка | `"run"` | `run`, `url`, `folder`, `update` (см. ниже) |
| `target` | строка | `game.executable` | Файл для `run`: `.exe`, `.cmd`, `.bat`; путь относительно папки игры |
| `args` | список или строка | `[]` | Аргументы запуска: `["-skip_reg", "-dbg"]` или `"-skip_reg -dbg"` |
| `url` | строка | — | Ссылка для `action: "url"` (обязательно `http://` или `https://`) |
| `path` | строка | — | Папка или файл для `action: "folder"` |
| `key` | строка | из `title` | Идентификатор кнопки (для логов); латиница выводится из названия, кириллица транслитерируется |
| `accent` | bool | `false` | Главная кнопка: акцентная заливка. Ставьте одной кнопке |
| `keep_open` | bool | `false` для `run`, иначе `true` | Оставлять лаунчер открытым после действия |
| `required_files` | список | `game.required_files` | Свой список проверок для этой кнопки |
| `hide_if_missing` | bool | `false` | Прятать кнопку, если `target`/`path` не существует |

`hide_if_missing` — самый удобный способ не показывать пользователю кнопки
«Менеджер модов» или «Папка логов», если этих файлов в сборке нет.

## Действия (`action`)

| Действие | Что делает | Обязательные поля |
| --- | --- | --- |
| `run` | Запускает файл из папки игры (процесс стартует в корне игры) | `target` или `game.executable` |
| `url` | Открывает ссылку в браузере по умолчанию | `url` |
| `folder` | Открывает папку или файл в проводнике (лог движка, `fsgame.ltx`, сохранения) | `path` |
| `update` | Проверяет релиз на GitHub и открывает страницу загрузки | `update.repo` |

## Пути и переменные окружения

* Пути в `assets`, `game.executable`, `target`, `path` считаются относительно
  папки, где лежит `config.launcher`.
* Абсолютные пути тоже работают.
* Поддерживаются `%LOCALAPPDATA%`, `$HOME`, `${VAR}` и `~`.
* В JSON обратный слэш нужно удваивать: `"path": "logs\\engine"`.

## Пример: минимальный конфиг

```jsonc
{
  "name": "Лаунчер мода «Северный ветер»",
  "accent": "#3f7d5a",
  "hero": { "title": "СЕВЕРНЫЙ ВЕТЕР", "subtitle": "версия 2.4" },
  "game": {
    "executable": "bin/xrEngine.exe",
    "required_files": ["bin/xrEngine.exe", "gamedata"]
  },
  "update": { "repo": "example-org/severny-veter" },
  "options": [
    { "title": "ИГРАТЬ", "description": "Запуск сборки", "args": "-nointro -x64", "accent": true },
    { "title": "СОХРАНЕНИЯ", "action": "folder", "path": "savedgames" },
    { "title": "ОБНОВИТЬ", "action": "update" }
  ]
}
```

Полный пример с комментариями по каждому полю — `examples/other-mod/config.launcher`
в репозитории лаунчера. Рабочий конфиг сборки CoC — `config.launcher` в корне.

## Проверка и типичные ошибки

```bash
Launcher.exe --check-config                     # проверить рядом лежащий файл
Launcher.exe --check-config --config путь\config.launcher
Launcher.exe --create-config путь\config.launcher
```

В CI лаунчера команда `--check-config` выполняется для примеров из репозитория —
сломанный конфиг не доедет до пользователей.

| Сообщение | Причина |
| --- | --- |
| `Файл настройки не найден` | Нет `config.launcher` рядом с лаунчером |
| `Синтаксическая ошибка JSON: Expecting ',' delimiter` + строка и `^` | Пропущена запятая или кавычка; в диалоге видно место |
| `У кнопки «X» не задано, что запускать` | Для `run` нет ни `target`, ни `game.executable` |
| `действие "url", но не заполнено поле "url"` | Кнопка ведёт в никуда |
| `не указан репозиторий` | Есть кнопка `update`, но пуст `update.repo` |
| `Ключ кнопки "x" повторяется` | Две кнопки с одинаковым `key` — задайте разные |
| `Не закрыт блочный комментарий /* ... */` | Незакрытый комментарий |

Ошибки не «съедаются»: они попадают в `launcher.log` полностью, вместе с
подсказкой и примером структуры.
